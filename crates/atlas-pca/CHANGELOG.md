# Changelog

## Unreleased

- Security (fail closed, 0.4.2 TS differential): `IntentV2Context::from_json` returned `None` for a PRESENT v2 context that is not a JSON object (JSON `null` included), so `.and_then(IntentV2Context::from_json)` silently switched Intent Layer v2 enforcement off on a misconfigured verifier, where the reference refuses. It now returns a malformed context (every v2 check that would be reported fails with `malformed v2 context: the v2 verifier context must be an object`); absent stays `None` at the call site. `from_json_text` keeps refusing non-object text.
- Fix (0.4.2 TS differential): the action handed to the layer ceilings, schema conformance and accumulators uses `String(p.action?.verb)` / `String(p.action?.resource)` like the reference (absent => "undefined"); a PCActn without `action.resource` no longer fails `layers` where TS passes. New `tests/intent_v2_diff.rs` runs the shared `k042-intentv2-cases` oracle: every decision agrees (47 reason texts still differ in wording, logged; `intent_v2_active` also counts a malformed context, as documented, where the TS helper does not).

- Security / Breaking (0.4.2, R3-01): a pure post-quantum or hybrid Intent Layer v2 session root verifies only under the VERIFIER's pin for its signer, the new verifier-context member `session.pq_pins` (`{<ed25519 key>: <pq_pk>}`), never under the root's own `principals[].pq_pk`. No pin fails closed (`session root suite '<alg>' needs the signer's PQ key pinned by the verifier (pq_pins) ...`), a pin that differs from the root's `pq_pk` fails, and a signer principals entry that declares another key fails. A malformed `pq_pins` (not an object of strings) is a malformed session context. Ed25519 roots are unchanged. Conformance `session-root-*-unpinned`, `-pin-mismatch`, `-pin-other-signer`, `-principal-entry-mismatch`, `ctx-session-pq-pins-*`. New `verify_session_root_pinned(s, pins)`; `verify_session_root(s)` is the no-pin form.
- Reason parity (rule 15): every refusal of the sequenced-receipt step (malformed receipt, clock / age, key set, signature) is the reference's single reason `the reservation receipt for '<id>' is not signed by a key the session sequencer's root-signed key set lists for its issue time` (it was the detail prefixed with `the reservation receipt for '<id>': `, e.g. `...: malformed receipt: receipt.expires_at must be within 900000 ms after issued_at`); an `unsupported_suite` refusal keeps its distinct reason. Verdicts unchanged. Found by the new conformance vector `acc-receipt-expires-before-issue`.
- Security (0.4.2 audit): `GuardResult::www_authenticate` emits only `PCA realm="pca", error="<code>"`. It used to append the description, which can carry request-derived text (the verdict reason, the presented `grant_ref`, a parse error); TS `requirePCA` puts no reason in its challenge either. The description stays in `json_body()`.
- Fix (fail closed, standalone chain API): `verify_chain_policy` given BOTH the verifier's stored grant (trusted root) and a PQ pin for the root issuer authorised the root on the stored grant and ignored a pin that names a different key. Both must now agree: a disagreeing pin refuses with `hop 0: root suite '<alg>': the server-side PQ pin for the root issuer (policy.pqPins) does not match the stored grant's pq_pk (fail closed)`, as in the TypeScript reference. The PCActn verify path passes only the stored grant and is unchanged. New shared vectors `chainpin-pure-pq-root-trusted-root-and-matching-pin`, `chainpin-pure-pq-root-trusted-root-wrong-pin`, `chainpin-hybrid-root-trusted-root-wrong-pin`.
- Rule 15 key-set equivocation (TS 5501b545): the tracked `acc.keyset_versions[root]` is exactly `{version, digest}` (`sequencer_key_set_digest`); a presented set at an older version (rollback) or another set at the tracked version (equivocation) is skipped, a malformed tracked entry fails `accumulators`. Rule 13 revocation evidence and the tracked last epoch refuse an unknown member (closed `{epoch, revoked}`, as the reference).
- Intent Layer v2 combined batch: rule 19 committed map (`intent_session.map_form: "commit"`, the `pca-intent:v2c:` goal with `intent_goal_commit_v2c`, the `map` check after `accumulators` with RFC 9162 openings, per-leaf salts, per-kind tags and the exact cell of the action, `decide_map_disclosure` / `map_commit_of_leaves` with runners and driver kinds `intent_map` / `intent_map_commit`); the v2 policy closed to `{session, schema, acc, map}` (`policy.acc.max_receipt_age_s` / `max_keyset_age_s`, `policy.map.require` / `max_residual_risk_ppm`, context `map: {disclosure?}`), a malformed context also failing `map` when the PCActn commits its map; rule 15 receipts live at most 15 min and must be fresh (`issued_at <= now + 60 s`, age <= A_r), key sets carry a required `version` >= the tracked `acc.keyset_versions[root]` and are at most A_k old, and a retired key stops verifying 60 s after its `not_after`; rule 13 step 7 is append-only by a dedicated revocation authority (`S.revocation.key` required and not a principal): the evidence is exactly `{epoch, revoked}` with the full sorted revoked list (`revset_root`), checked against the tracked `session.revocation_last` (no rollback, drop or equivocation); the proof-based non-membership API is removed.
- Intent Layer v2 follows d63b36e6 / ab9766e0 / ca361968 / 0cc44911: the W-B artifacts (`pca-fact`, `pca-offer-set`, `pca-labels`, `pca-intent-classification`) may carry signed `alg` / `pq_pk` and `pq_sig`; their suite is checked FIRST (a non-string `alg` is malformed, an alg the dispatch refuses fails with `unsupported_suite`, a classical artifact carries no `pq_pk` / `pq_sig`) and a PQ / hybrid signature verifies only under the PQ key the verifier pins (oracle / site / label key `pq_pk`, classifier `pq_keys`); the artifact message excludes `pq_sig`. Every v2 and W-B policy is closed and typed: `policy` is exactly `{session?: {require?: bool, max_revocation_age_s?}, schema?: {closed_world?: bool}}` (anything else is a malformed context that fails `schema`, `intent_session` and, with the member, `accumulators`, also without `intent_session`); the world policy, worlds, oracle pins, relational entries, offers, site keys, filter, provenance policy, label keys, classifier policy and classifiers have closed member sets; a ceiling is exactly `{predicates}` (an extra member fails `layers` as that ceiling). `decide_intent_wb` refuses a malformed W-B context exactly as `intentWBContextError` (intent_session an object; closed `artifacts` / `policy` with typed members) at `facts`; rules 16-18 need an `action` object. Provenance class lists sort in UTF-8 byte order. New `decide_read_purpose` (`primitives.intent_read_purpose`, driver kind `intent_read_purpose`). The runner checks `reason_contains` / `requires_suite` on the W-B primitives and no longer panics on a non-integer clock.
- Suite capability (packages/pca/conformance/SUITES.md): the ONE suite dispatch (`resolve_sig_alg` / `verify_suite`, used by the leaf, capability hops, threshold shares, chain pins and the Intent v2 artifacts) now implements every registered suite Rust has a vetted pure-Rust primitive for: `ml-dsa-65`, `ml-dsa-87` (fips204), `slh-dsa-sha2-128f`, `slh-dsa-sha2-256s` (new dependency fips205 0.4, the crate the zkVM guest uses), their `hybrid-ed25519-*` forms, the SUF-CMA `hybrid-nested-ed25519-ml-dsa-65`, and `fn-dsa-512` / `fn-dsa-1024` (new dependency fn-dsa-vrfy 0.4, the crate the TS reference wraps; DOMAIN_NONE + HASH_ID_RAW). Pure mode, empty context, per-suite lengths. `less-cat1` / `hybrid-ed25519-less-cat1` fail closed with the distinct reason `unsupported_suite: <alg>`; an unregistered alg keeps `unknown signature alg`. New public `REGISTERED_SUITES`, `supported_suites()`, `UNSUPPORTED_SUITE_REASON`, `verify_artifact_suite(artifact, ed_pub, msg)` (caller-vouched PQ key). Tests: runners take the manifest and assert `unsupported_suite` instead of skipping; `tests/suite_capability.rs` runs the FN-DSA known answers of packages/pca/conformance/fndsa-vectors.json. The diff-fuzz driver answers kind `suites` and tags `unsupported_suite` verdicts.
- Intent Layer v2 follows the strict W-A pass (5e0a33a9, README "strict values, absent vs null, suite capability"): a malformed top-level verifier context (`intent_v2_context_error`: policy / policy.session / policy.schema, params, schema, session, acc, layers and each ceiling `{predicates: [...]}`, wb and its artifacts / policy members) fails `schema`, `intent_session` and (with the member) `accumulators`, and no layers / W-B check is reported; a clock that is not a safe integer fails every reported v2 check; policy flags are on only as `true`; schema / session / acc sub-contexts typed (schema needs `docs` and `keys` arrays, last_seq values safe integers); held session grants must be capabilities with an implemented suite (`unsupported_suite`); revocation epochs and non-membership proofs strictly shaped (`revocation_epoch_shape_error`, `non_membership_proof_shape_error`) and a PQ epoch verifies only under the key S pins (`principals[].pq_pk`, new `revocation.pq_pk`; `check_session_revocation` takes the pins); `S.layers.org` / `std` null is malformed; `__proto__` / `constructor` / `prototype` refused as accumulator / monitor ids and schema parameter names; a schema `default: null` is malformed; a non-string `alg` is malformed (not `unsupported_suite`). The runner fails (rather than skips) a `requires_suite` vector this build lacks unless it fails with `unsupported_suite`, and checks `expect.reason_contains`.
- Intent Layer v2 strictness (README rulings): every v2 signature (session root, action schema, reservation receipt, sequencer key set, revocation epoch) goes through the crate's suite dispatch and fails closed with `unsupported_suite` when it refuses the alg; nothing is coerced (safe integers are rule 3's, lists are JSON arrays, lookups are own members, the vote tally is an ordinary map); an absent optional member is empty / default while a JSON `null` (or a wrong container type) is malformed and fails, closed, the check that owns it (a malformed `policy.schema.closed_world` / `policy.session.require` reports its check as failed; a malformed `wb` input fails `facts`); W-B follows the 053ee5c2 rule text (a clock that is not a safe integer makes facts and offer sets stale, strict activity typing, new `intent_wb_active` for `primitives.intent_wb_active`). The conformance runner skips vectors whose `requires_suite` this build lacks.
- Intent Layer v2 (additive, rules 13-18 of the conformance README): `intent_session` is a new OPTIONAL SIGNED top-level PCActn member (closed wire: `session`, `root`, `schema`, `seq` in [0, 2^31-1], `acc`, `facts`, `offer_set`, `prov`, `classes`, `labels`; a malformed member fails `wire`). With it the `intent` check opens the v2 goal `pca-intent:v2:<session>:<map_digest>` (new `intent_goal_commit_v2`). `VerifyOptions` gains `intent_v2: Option<&IntentV2Context>` (the verifier state as JSON, `IntentV2Context::from_json` / `from_json_text`), and after `intent` the verdict reports, in order and only under the README reporting rules, `schema` (signed action schemas, closed-world conformance), `intent_session` (session root S, principal-signed delta chain, session revocation epochs with sorted-Merkle non-membership), `layers` (org / site / std ceilings through a port of the full predicate DSL and its linear-time regex engine), `accumulators` (site-local pre-state arithmetic, monitors, sequencer reservation receipts resolved through the sequencer's root-signed `pca-sequencer-keys` set: kid, validity window, suite, +60 s skew), then the W-B unit `facts` / `provenance` / `classes` (oracle facts with lower median and relational dimensions, offer sets, per-parameter provenance with label receipts and flow rules, classifier quorum). The rule-10 caveat evaluator treats a well-formed `intent_session` caveat as satisfied. Without the member and without an active v2 policy the verdict is unchanged. - Intent Layer M2 (additive): `intent` is a new OPTIONAL SIGNED top-level PCActn field (`{ref, map_digest, goal_salt, fidelity_ppm, residual_risk_ppm}`, closed member set; a malformed slot fails `wire`). New `IntentPolicy { require, min_fidelity_ppm: Option<f64>, max_residual_risk_ppm: Option<f64> }` (with `is_active` and the lenient `IntentPolicy::from_json`), `VerifyOptions { allowed, intent }`, `verify_pcactn_core_with` / `verify_pcactn_json_with`, `intent_goal_commit(ref, map_digest, goal_salt)` and `MAX_INTENT_GOAL_SALT_LEN`. Existing entry points keep their signatures; without the slot and without a policy the verdict is unchanged. The conformance runner and the diff-fuzz driver pass `intent_policy` through.
- Intent policy thresholds are judged by NUMERIC VALUE whatever the lexical form (`950000.0`, `1e6` valid; `-0`, `-0.0`, fractions, negatives, > 2^53-1, null/bool/string misconfigured). ## 0.4.1 - 2026-10-12

- Security (policy layer): caveats on the root grant outside the envelope are now evaluated like delegated caveats; new policy_caveats/evaluate_caveats helpers (incl. max_spend). The core verifier still does not evaluate caveats. (`policy_caveats(&grant, &chain)` / `evaluate_caveats(&caveats, &ctx) -> (ok, failed)`, exercised by the shared `primitives.caveat_eval` vectors.)
- Threshold shares (wire): `threshold.shares[i]` signatures are validated per suite like the leaf (`alg` absent = ed25519 with a 64-byte `sig`; `ml-dsa-65` a 3309-byte `sig`; `hybrid-ed25519-ml-dsa-65` a 64-byte `sig` plus a required 3309-byte `pq_sig`; `pq_sig` must be absent otherwise; a non-string or unknown `alg` fails). Before, every share `sig` had to be exactly 64 bytes, so a pure ML-DSA-65 share could never be carried, and a stray or missing `pq_sig` was not caught at the wire stage. A share's `pq_pk` stays an optional echo judged by the threshold check.
- Strict `PCA-Action` header: new public `decode_pca_header` (strict unpadded base64url, no trimming, canonical trailing bits, strict UTF-8, BOM kept) used by the `axum` middleware's header path; any failure is the existing `401`. Exercised by the shared `primitives.pca_header` vectors.

## 0.4.0 - 2026-10-11 (BREAKING)

- Depth / strict digests (security, parity): every protocol digest the verifiers compute (hop body digest, parent capability hash, caveat comparison, root-vs-grant, root `trusted_root` match, Merkle leaves; new public `hash_canonical_strict`) now uses the STRICT canonical form like the reference (`hashCanonical` is `canonicalizeStrict`): depth <= 32, safe integers, plain decimals. It was the lenient form, so a correctly SIGNED hop carrying a depth-33 value, `1e300` or `2^53+2` verified although the reference refuses the chain; now `hop N: malformed body`. `merkle_root` errs on an out-of-profile leaf. A caller-built hop deeper than the cap is measured iteratively BEFORE the body is cloned (a recursive clone of a 1,000,000-deep value overflowed the stack and aborted the process). `hash_canonical` / `cap_hash` / `params_digest` stay lenient (content addressing only).
- R6-01 (security): the tower/axum middleware's body mode parses the `{"pcactn": ...}` envelope with the strict profile (new `strict_parse_envelope`; depth cap `MAX_JSON_DEPTH` over the whole envelope, as the reference's `defaultExtract`) instead of `serde_json::from_slice`: duplicate keys anywhere are refused, as in header mode (a lenient parse collapsed them last-wins before verification).
- R6-03/R6-04 (parity): `verify_threshold_share` validates the WHOLE signer set like the reference (unknown or wrong-case roles, malformed keys, empty / null / short `pq_pk` anywhere, one key per role, one role per key, a duplicate (role, key) only with the same `pq_pk`); `t` must be 1, 2 or 3 (0..=255 was accepted); `share.role` is required. New `signer_set_hash_b64u`.
- R6-05 (robustness): `verify_chain` applies the reference per-hop type check (`id`/`issuer`/`holder`/`body_digest`/`sig` strings; `alg`/`pq_pk`/`pq_sig`/`holder_pq`/`parent` absent or strings; caveats objects with a string `type`): correctly SIGNED but ill-typed hops (numeric caveat, caveat without `type`, numeric `holder_pq`/`holder`, object `caveats`) and a hop with a numeric `pq_pk` were accepted. No public verify entry point panics on the shared `malformed` vectors.
- R6-02 (security): a signer-set role that registers a `pq_pk` now REQUIRES a PQ (pure or hybrid) threshold share; an ed25519-only share for that role is refused, so an Ed25519 break no longer forges a hybrid-registered role (parity with the TypeScript reference). Corpus: `agent-bound-signerset-with-pq-pk` is now `valid:false`; new positive `agent-hybrid-signerset-with-pq-pk`.
- R5-A1 (security): threshold-share verification is now signer-set PINNED, no longer self-vouched. The share must be for the one key the signer set registers for its role, a PQ/hybrid share verifies only under the set's registered `pq_pk` (a differing share `pq_pk` is refused), the share-suite tag is part of the signed bytes (a classical share cannot be relabelled hybrid), and the signer-set hash now includes a registered `pq_pk` (parity with the TypeScript reference). New corpus vectors: `agent-not-in-signer-set`, `agent-bound-signerset-with-pq-pk`, `agent-hybrid-relabel-*`.

- Suite policy defaults documented: no list = no restriction, an empty list refuses everything, and the hosted API defaults to ed25519 + Ed25519 hybrids (README lists the exact list to pass offline).

- BREAKING (security, R4-01): the standalone chain verifier now takes a non-ed25519 root's PQ authority from the verifier, exactly like the TypeScript reference (R3-01). `verify_chain_policy` gains two trailing arguments, `pq_pins: Option<&HashMap<String, String>>` (root issuer, Ed25519 base64url, to its ML-DSA public key) and `trusted_root: Option<&Value>` (the verifier's own stored root capability). A pure `ml-dsa-65` or hybrid ROOT hop is accepted only if `trusted_root` has the same content hash as the root, or `pq_pins` has an entry for `root.issuer` equal to the root's `pq_pk` (a differing pin is a refusal). Otherwise it is refused with `hop 0: root suite '<alg>' needs a PQ key pinned for the root issuer (policy.pqPins) or the verifier's stored grant (policy.trustedRoot); the root's own pq_pk proves nothing about who issued it (R3-01)`. Before, an attacker-minted root naming a victim Ed25519 issuer, signed with the attacker's own ML-DSA key, verified. Migration: callers of `verify_chain_policy` on a root they did not load from their own store pass `Some(&pins)`, or `Some(&stored_root)`, else `None, None`; `verify_chain` (two arguments) keeps its signature but now refuses every non-ed25519 root. Ed25519 roots are unaffected. `verify_pcactn_core*` is unchanged in behaviour (it passes its grant as `trusted_root`). Internally one `pinned::resolve_pq_key` choke point mints the only key type the suite verifier accepts, so PQ verification cannot be reached with a `pq_pk` read off the artifact.

- BREAKING (security, R3-03): hop and leaf signatures under `ml-dsa-65` / `hybrid-ed25519-ml-dsa-65` are now accepted only if `pq_pk` hashes to the signer's committed `holder_pq` (hop `holder_pq` is now part of the wire format and the signed hop body). Unbound or attacker-supplied PQ keys are rejected, exactly like the TypeScript reference. New `verify_pcactn_core_policy` / `verify_pcactn_json_policy` / `verify_chain_policy` take an optional allowed-suites list (`None` = none, `Some(&[])` refuses everything).
